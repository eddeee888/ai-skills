# Shared conventions: posts

## Comment labels: bold when writing, either form when reading

Every inline comment starts with bold `**Question:**`, `**Suggestion:**`, `**Issue:**`, `**Test:**`, `**Note:**`, or `**Drive-by:**`. Readers match bold and plain forms equally (`Note:` = `**Note:**`). Thread replies never open with a label; a signed reply remains a reply.

## Comment body: short, one point per bullet

*Default* — the user's ask in this conversation, or an `overrides:` line in the `pr-oracle` profile naming this section (without the oracle: a different rule in the repo's `CLAUDE.md` or `CONTRIBUTING.md` — "Companion plugin: `cops`"), replaces it ("Defaults and contracts").

Every inline comment, reply, review body, and issue comment is only as long as needed:

- One point → one or two sentences.
- Multiple points/sources → one answer sentence, then one point per bullet, source at that bullet's end. A bullet may contain a needed code block.
- Remove restated questions, visible diff/thread facts, hedges, and repetitive closings.
- Label stays first line and is not repeated; signature is its own final paragraph.

Issue and PR descriptions use their templates.

## Citing sources: a link readers can open

*Default* — the user's ask in this conversation, or an `overrides:` line in the `pr-oracle` profile naming this section (without the oracle: a different rule in the repo's `CLAUDE.md` or `CONTRIBUTING.md` — "Companion plugin: `cops`"), replaces it ("Defaults and contracts").

Every source in posted GitHub text is an openable link.

- **Code** → commit-pinned permalink `https://github.com/<owner>/<repo>/blob/<sha>/<path>#L<line>` with `` `<owner>/<repo>` `<path>:<line>` `` link text. An unlinked path is not a source.
- **Anything else** → its URL.
- **Readers can open it.** Permit the post's repo, public repos, or public URLs. Check each distinct repo once via `gh api repos/<owner>/<repo> --jq .private` or MCP `get_file_contents`; judge other URLs by host without fetching and treat uncertainty as private. Keep private/sign-in-only sources out, tell the user in-session, and answer from public evidence or state backing is private.
- **Already referenced.** Existing PR/issue links, including issue-tracker/body/commit links, remain even if private.

## Skill signature: `<sub>_Skill: [<plugin>:<skill>](…)_</sub>`

*Default* — the user's ask in this conversation, or an `overrides:` line in the `pr-oracle` profile naming this section (without the oracle: a different rule in the repo's `CLAUDE.md` or `CONTRIBUTING.md` — "Companion plugin: `cops`"), replaces the writing rule; the reading rule always applies ("Defaults and contracts").

**Writing.** Every inline comment, reply, review body, issue, and issue comment ends with:

```markdown
<sub>_Skill: [cops:pr-review](https://github.com/eddeee888/ai-skills/tree/main/cops/skills/pr-review)_</sub>
```

If the user approved the post or reported work, append inside italics:

```markdown
<sub>_Skill: [cops:pr-review](https://github.com/eddeee888/ai-skills/tree/main/cops/skills/pr-review) · Approved: [<login>](https://github.com/<login>)_</sub>
```

`Approved:` means the user confirmed drafted text or authorized the work reported, including `pr-address` thread go-ahead/Step 4 answer. Omit it for unseen new why-answers. Use login from `gh api user --jq .login` or `get_me`; no `@`.

- Signature is its own paragraph after all content, including ```suggestion```. Empty review body stays empty. PR titles/descriptions are unsigned.
- Required host footer (for example `Generated by Claude Code`) remains unchanged after the signature; nothing follows it.
- Signed bodies are multi-line and use a file on the `gh` route.

**Reading.** A final line before host footer matching this `<sub>` format, `Skill: <plugin>:<skill>`, and linked into `github.com/eddeee888/ai-skills` identifies skill-authored text even under the user's login. The label determines meaning:

- `Question:`/`Suggestion:`/`Issue:`/`Test:` → user's ask.
- `Note:`/`Drive-by:` → explanation.
- No label → skill reply: never go-ahead, new ask, or preference; if last in a thread, that thread is handled.

## Author notes: `Note:` / `Drive-by:`

The PR author's inline `Note:` explains a choice the task did not specify; `Drive-by:` explains why an unnecessary change is included. For an opening author label in either form:

- Nobody else commented → handled; do not implement or answer.
- Someone replied → classify from the last comment.
- It prevents another `Question:` on explained lines, but not a critical `Issue:`.

Asks never use these prefixes. `cops:pr-note` posts author reasoning on the author's own PR only after the user confirms the draft.

## Critical changes

A critical/dangerous change (including breaking or hacky user-impacting behavior) warrants a comment even if the checked path works. Raise `Issue:` and suggest a `// FIXME` naming the problem. An author note may answer `Question:` but never retires this.
